# Arbitrum & Rollup

---

## 以太坊为什么需要扩展

以太坊每秒只能处理约 **15 笔交易**，网络拥堵时一笔 USDT 转账手续费可达 $50。

原因：全网节点都要执行每笔交易，节点越多越去中心化，但速度越慢。

---

## Rollup 是什么

**把交易搬到链下算，只把结果提交到以太坊。**

```
没有 Rollup：1000笔交易 → 全部在以太坊执行 → 拥堵、贵
有了 Rollup：1000笔交易 → 在链下执行 → 打包成1条摘要 → 提交以太坊
```

**类比**：
- 每个员工报销都找老板签字 → 财务部汇总成一张清单 → 老板只签一次
- 以太坊 = 老板（最终裁判），Arbitrum = 财务部（批量处理）

**结果**：速度提升10倍以上，手续费降到几美分，安全性继承以太坊。

---

## Arbitrum 的安全机制：挑战期

```
清单提交后 → 7天公示期 → 任何人可提出挑战 → 以太坊仲裁
没人挑战 → 7天后自动生效
```

造假成本极高（没收押金），实际上没人敢造假。

这种方式叫 **Optimistic Rollup**（乐观型）——默认相信提交是正确的，出问题再挑战。

## 竞争格局

| 项目 | 类型 | 特点 |
|------|------|------|
| Arbitrum | Optimistic Rollup | 以太坊L2 TVL第一 |
| Optimism | Optimistic Rollup | 技术路线相近，生态略小 |
| zkSync | ZK Rollup | 数学证明替代挑战期，更安全但工程难度更高 |
| StarkNet | ZK Rollup | 同上 |

**ZK Rollup vs Optimistic Rollup**：
- Optimistic：默认信任，出错再挑战，有7天延迟
- ZK：每次提交附带数学证明，即时验证，无需等待，但更难建
