## 一、比特币没有"余额"，只有 UTXO

这是小白最容易卡住的地方，但搞懂了它，比特币的一切都通了。

### 银行的账本 vs 比特币的账本

```
银行（账户模型）              比特币（UTXO 模型）
┌──────────────┐            ┌────────────────────────┐
│ 张三  10,000 │            │ 收据A：给张三 3 BTC    │
│ 李四   5,000 │            │ 收据B：给张三 5 BTC    │
└──────────────┘            │ 收据C：给李四 2 BTC    │
                            └────────────────────────┘
张三的余额 = 数据库里的一个数    张三的余额 = 把所有写他名字的
                                 未花费收据加起来 = 8 BTC
```

**UTXO = Unspent Transaction Output = 未花费的交易输出**，说人话就是**一张还没被花掉的收据**。

比特币的账本里**根本没有"张三 = 8 BTC"这一行**。钱包显示的 8 BTC 是它替你扫描全链、把所有属于你的收据加起来算出来的。

### 花钱的过程 = 撕旧收据、开新收据

张三要付 4 BTC 给王五：

```
输入（销毁）              输出（创建）
收据B：5 BTC  ──────→   新收据①：给王五  4 BTC
                        新收据②：给张三  0.9999 BTC  ← 找零给自己
                        
                        差额 0.0001 BTC = 矿工手续费
```

**三个关键点**：

1. **收据不能拆着用**。要花 5 BTC 收据里的 4 BTC，必须把整张撕掉，重开一张 4 BTC 的和一张找零的。跟你用 100 块买一瓶 4 块的水，找回 96 块，是一模一样的逻辑。
2. **手续费不是单独写的一项**。输入总额减输出总额，剩下的自动归矿工。⚠️ **如果你填错，把 5 BTC 全填成手续费，矿工照收不误，钱找不回来。** 历史上真实发生过这类误操作。
3. **找零地址通常是新地址**。所以你会在区块浏览器上看到自己转账后钱"跑到一个陌生地址"——那多半是你自己的找零地址。

### 为什么用这么反直觉的设计

| 好处 | 说明 |
|------|------|
| **天然防双花** | 一张收据被引用过就作废了。节点只需检查"这张收据还在不在未花费集合里" |
| **可并行验证** | 不同 UTXO 之间没有依赖，可以同时验证。账户模型必须按顺序改余额 |
| **隐私略好** | 每次找零换新地址，不像账户模型所有活动挂在一个地址下 |

| 代价 | 说明 |
|------|------|
| **难写复杂逻辑** | 没有"全局状态"这个概念，写不了"记住某个变量" |
| **UTXO 集合会膨胀** | 全网所有未花费收据必须被每个节点常驻内存，是长期负担 |
| **对开发者不友好** | 这是以太坊后来改用账户模型的直接原因 |

## 二、挖矿到底在算什么

### 一句话：在猜数字

矿工要做的事：把待打包的交易列表 + 上一个区块的哈希 + 时间戳 + **一个随机数（nonce）** 塞进哈希函数，看输出结果是不是**小于某个目标值**。

```
SHA256(区块头 + nonce = 0)        → 8f3a2b...  太大，不行
SHA256(区块头 + nonce = 1)        → c7d91e...  太大，不行
SHA256(区块头 + nonce = 2)        → 2b4f8a...  太大，不行
...试了 10^22 次...
SHA256(区块头 + nonce = 8873...)  → 000000000000000000012a4f...  ✅ 够小！
```

**哈希函数的关键性质：不可逆。** 你没法从"想要的结果"倒推出 nonce，**只能一个一个试**。这就是"工作量"的来源——除了暴力穷举，没有任何捷径。

> 🚫 **常见误解**：挖矿不是"解密码"，也不是在做科研计算。这个计算的结果**对外部世界毫无价值**。它唯一的作用是当一张收据：**证明我确实烧了这么多电。** 这是设计意图，不是浪费的副作用。

### 难度调整：让出块速度锁死在 10 分钟

全网算力涨了，题就该变难；算力跑了，题就该变简单。

```
每 2016 个区块（约两周）自动调整一次

实际耗时 < 2 周  →  难度上调（题变难）
实际耗时 > 2 周  →  难度下调（题变简单）

目标：永远维持平均 10 分钟出一块
```

这是比特币最优雅的设计之一：**无论全世界投入多少算力，比特币的发行速度纹丝不动。** 2021 年中国清退矿场，全网算力一夜掉 50%，比特币只是出块变慢了两周，然后难度自动下调，一切恢复正常【A：链上难度调整记录可公开验证】。

## 三、2100 万的硬上限是怎么来的

### 减半机制

```
2009-2012   每块奖励 50    BTC
2012-2016   每块奖励 25    BTC   ← 第1次减半
2016-2020   每块奖励 12.5  BTC   ← 第2次减半
2020-2024   每块奖励 6.25  BTC   ← 第3次减半
2024-2028   每块奖励 3.125 BTC   ← 第4次减半（2024年4月）【A】
2028-       每块奖励 1.5625 BTC  ← 第5次减半，预计 2028年4月，区块高度 1,050,000【B】
...每 21 万个区块（约4年）减半一次
```

等比数列求和，总量收敛于 **2100 万枚**。约 2140 年发完最后一枚。

**当前状态（2026-08）**：每块奖励 3.125 BTC，处于第四次减半周期内。

### 为什么这件事重要

```
法币：发行量由央行决定 → 可以无限增发 → 通胀由人的决策产生
比特币：发行量写死在代码里 → 全网节点共同执行 → 通胀由数学产生
```

这是比特币"数字黄金"叙事的全部基础。**能不能改？** 理论上改代码就行，但需要全网绝大多数节点自愿升级——而**持币者没有任何动机去稀释自己**。这是社会共识层面的锁，比技术层面更硬。

### 一个真实的长期问题

区块奖励最终会趋近于零，那时矿工只能靠**手续费**活着。

```
现在：矿工收入 ≈ 区块奖励（大头）+ 手续费（小头）
未来：矿工收入 = 手续费（全部）
```

⚠️ **如果那时手续费收入不足以支撑足够的算力，比特币的安全预算就会下降。** 这是比特币最被认真讨论的长期风险，至今没有公认解法。【推测】这也是为什么"比特币要不要承载更多数据/应用"这个问题在社区里能吵到撕裂——它直接关系到手续费市场能不能长起来。

## 四、分歧了听谁的：最长链规则

两个矿工同时挖出块，网络会短暂分叉：

```
        ┌─ 区块101a ─ 区块102a ─ 区块103a  ← 这条更长，胜出
区块100 ┤
        └─ 区块101b                        ← 被抛弃（孤块）
```

规则：**跟随累计工作量最大的那条链。** 落败链上的交易回到待打包池，重新等待。

### 所以"确认数"是什么意思

| 确认数 | 含义 | 实践中的用法 |
|--------|------|------------|
| 0 确认 | 交易还在内存池，没进块 | 有被替换的风险，不能视为完成 |
| 1 确认 | 进了 1 个块 | 小额可接受 |
| 6 确认 | 后面又压了 5 个块（约1小时） | 交易所常用的入账标准 |

**为什么是 6**：白皮书里算过，攻击者要推翻 6 个确认，需要的算力和运气在经济上已不现实【A：白皮书第11节】。这是个经验值，不是魔法数字。

### 51% 攻击的真相

掌握全网 51% 算力，你能做的：
- ✅ 双花自己的币（撤销自己近期的交易重新花一次）
- ✅ 拒绝打包某些交易（审查）

你**不能**做的：
- ❌ 凭空造币（违反共识规则，节点直接拒绝）
- ❌ 花别人的币（你没有别人的私钥）
- ❌ 修改久远的历史（成本随深度指数上升）

> 【B】51% 攻击**在小市值 PoW 链上真实发生过**——Ethereum Classic（2019、2020 多次）、Bitcoin Gold（2018、2020）等。原因是它们的算力可以直接在算力租赁市场上租到，攻击成本远低于收益。**比特币没被攻击过不是因为不可能，是因为算力规模让它不划算。**

## 五、比特币为什么"不可编程"

比特币有脚本语言（Script），但它是**故意做残的**：

| 限制 | 后果 |
|------|------|
| **非图灵完备**，没有循环 | 写不了复杂逻辑，但也不可能死循环卡死全网 |
| **无全局状态** | 合约记不住任何东西，每笔交易独立 |
| **操作码极少**，很多还被禁用 | 能表达的逻辑非常有限 |

**这是取舍不是缺陷。** 中本聪选择了"可预测、可验证、攻击面小"，代价是"做不了应用"。

以太坊选了反方向：图灵完备、有全局状态、能写任意逻辑——代价是**智能合约漏洞成了整个行业最大的死因**。

> **两条路线没有对错，只有取舍。** 比特币 17 年没有因为协议漏洞丢过币；以太坊生态每年被黑几十亿美元。反过来，以太坊上长出了 DeFi、稳定币、NFT，比特币上什么都没有——这也是为什么后来有了 RGB、Ordinals、Taproot Assets 这些"想在比特币上做点事"的尝试（见[卷三 3.11 比特币生态](../README.md)、[基础 01](../../basics/01-bitcoin-rgb.md)）。

## 六、比特币的三次重大升级

| 升级 | 时间 | 干了什么 |
|------|------|---------|
| **SegWit（隔离见证）** | 2017-08 | 把签名数据挪出交易主体，修复交易延展性，变相扩容 |
| **Taproot** | 2021-11 | 引入 Schnorr 签名和 MAST，多签在链上看起来和普通转账一样（隐私+省空间）【A】 |

**Taproot 当前采用率**：截至 2026 年 4 月，Taproot 交易约占比特币交易活动的 **1/5** 左右，低于铭文热潮时期的峰值，但显著高于激活后第一年的水平【B】。

> ⚠️ 注意时点：Taproot 采用率数据波动很大，跟铭文/序数的热度直接挂钩。引用时必须带日期。

## 七、正在吵的架：Core vs Knots

**这是 2025–2026 比特币社区最大的分裂，不了解会看不懂很多推特骂战。**

### 起因：OP_RETURN 限制被放开

- `OP_RETURN` 是比特币交易里一个可以写任意数据的字段，长期默认限制约 80 字节
- **Bitcoin Core v30（2025年10月10日发布）把默认上限提到 100,000 字节**，实际上等于取消限制，并允许一笔交易里有多个 OP_RETURN 输出【A：Bitcoin Core v30 release notes】

### 双方的理由

```
Core 维护者一方：
  80 字节的限制早就失效了——数据本来就在通过 Taproot witness 塞进来。
  而绕过限制的那些做法更糟：撑大 UTXO 集合，或者把交易推到链下私下给矿工，
  让公共内存池失去可见性。
  → 与其假装限制有效，不如承认现实。

反对方（Knots 阵营）：
  这等于官方给"把比特币当数据存储盘"开绿灯，
  区块空间被非货币用途挤占，节点存储负担上升。
  → 比特币应该只做钱。
```

### 关键事实

- **这是 policy（策略）变更，不是 consensus（共识）变更**【A】。意思是：它改的是"节点默认愿不愿意转发/打包这类交易"，**不改变什么交易是合法的**。不同意的人可以改配置，或者直接跑 Bitcoin Knots。
- 节点软件分布【C】：2026 年 Q2–Q3 预计稳定在 Core 约 65–80%、Knots 约 15–20%。⚠️ 这是预测数据，不是实测，引用需谨慎。

> 【推测】这场争论表面是技术之争，底下是**比特币身份之争**：它是纯粹的货币，还是一个可以承载更多东西的结算层。这个问题会持续影响整个比特币生态赛道的走向。

## 九、一句话总结

> **比特币用"猜数字比赛"决定谁记账，用"减半"锁死总量，用"最长链"解决分歧，用"故意做残的脚本"换取十七年零协议事故。它做不了应用，这是设计选择，不是能力不足。**

## 十、常见误解

**误解 1：比特币能追踪，所以不匿名/所以完全匿名**
两个方向都错。比特币是**假名（pseudonymous）**：地址不直接绑定身份，但**所有交易永久公开可查**。链上分析公司（Chainalysis、Arkham）能把地址和真实身份关联起来的成功率很高。⚠️ **"比特币适合洗钱"是过时认知**——它是最不适合的资产之一，因为账本永远在那里。

**误解 2：丢失的比特币会被"回收"**
不会。私钥丢了，那些 UTXO 就永远躺在链上不可花费。【B】据多方估算约有数百万枚 BTC 处于永久丢失状态，这等于变相通缩。

**误解 3：矿工可以随便打包交易赚钱**
矿工只能**选择打包哪些交易**（通常按手续费排序），不能伪造交易。你的币没有你的签名，谁都动不了。

**误解 4：比特币每秒只能处理 7 笔交易，所以没用**
这个数字大致对（受区块大小和交易结构影响），但**比较对象错了**。比特币定位是**结算层**，不是零售支付层——就像你不会拿央行的大额清算系统去买咖啡。零售层的方案是闪电网络等二层。

**误解 5：中本聪持有大量比特币会砸盘**
【B】链上确实存在约 100 万枚归属于早期挖矿模式（"Patoshi Pattern"）的 BTC，且这些币自挖出后**从未移动过**。但"这些币属于中本聪"是**推断而非确证**，且它们是否还有人能动都是未知数。传播时应说明这是推断。
