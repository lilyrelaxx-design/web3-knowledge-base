# Hyperliquid 全解析

---

## 是什么

**一条为交易而生的公链**，不是"链上的交易所"。

普通项目：区块链 → 智能合约 → 搭个交易所
Hyperliquid：区块链**本身**的原生功能就是撮合订单

这个区别是理解它所有业务的钥匙。结果：0.2 秒成交、挂单撤单近乎免费，但资产在你自己钱包里。

**永续合约**：带杠杆的合约交易，可做多做空，没有到期日。

## 两层架构：HyperCore vs HyperEVM

| | HyperCore | HyperEVM |
|---|---|---|
| 是什么 | 交易引擎本体 | 通用智能合约层 |
| 干什么 | 永续、现货、订单簿、清算 | 借贷、LST、稳定币等 DeFi |
| 上线时间 | 2023 | 2025年2月 |
| 现状 | 核心营收来源（90%+） | 175+ 团队部署 |

两层共享同一批 HYPE 和资产，可以互转。HyperCore 是交易所主体，HyperEVM 是开放给别人建应用的地皮。

## 当前业务结构

| 业务 | 说明 | 权重 |
|------|------|------|
| 永续合约 | 链上永续第一，OI 市场份额长期 ~70% | 核心（90%+ 收入） |
| 现货 + 代币发行 | HIP-1 原生代币标准 + HIP-2 内置做市机制 | 成长中 |
| HLP 金库 | 用户存 USDC，资金池做市/接清算单，赚做市收益 | 补充 |

**HIP-1**：Hyperliquid 的原生代币标准，相当于以太坊的 ERC-20。
**HIP-2**：内置做市机制，新币上线自带流动性，无需手动做市。
**HLP（Hyperliquidity Provider）**：散户存 USDC 进金库，系统自动做市和接清算单。**注意：不是无风险理财**，做市亏损会从本金里扣。

> **HLP 的激励错配**：2026年1月31日一笔 7.3 亿美元的 ETH 清算，让 HLP 亏损约 2.5 亿美元，
> 而同一天协议自己赚了 1500 万手续费。金库承担风险、协议收手续费——这个结构被社区激烈批评。

## 技术难点

### 难点一：共识太慢
**解法**：自建链 + HyperBFT 共识算法，只有约20个验证者节点，2/3同意即出块。
**代价**：去中心化程度低于以太坊。

### 难点二：订单簿上链太贵
在以太坊上挂单/改价/撤单每次都要付Gas费，高频交易完全不可能。

**解法**：订单簿操作是链的**原生功能**，不走智能合约。
```
以太坊：所有操作 = 智能合约调用 = 交易 = 付费
Hyperliquid：挂单/撤单 = 链内置操作 = 极低费用
```

### 难点三：清算必须跑赢市场
慢链上清算指令等待打包期间，价格继续跌，亏损扩大。

**解法**：清算引擎内置于链，价格触线→链自动执行，0.2秒内完成。

### 难点四：Oracle 问题（最难、未完全解决）
永续合约需要链外真实价格（标记价格）触发清算和资金费率。

**风险**：Oracle被操控 → 假价格触发错误清算。
**Hyperliquid解法**：多数据源聚合 + 验证者投票兜底，极端情况仍需人工干预。

**JELLY事件（2025年3月）**：
```
巨鲸在Hyperliquid开巨额空单 → 在外拉高JELLY价格
→ 试图让Hyperliquid金库爆仓
→ 验证者投票强制平仓，按自定价格结算
```
争议：这说明极端情况下它仍是"人工决策"，去中心化存疑。

### 难点五：MEV（抢跑攻击）
你的交易发出但未打包时，矿工/验证者可以看到并抢在你前面成交，从中获利。

**解法**：验证者控制交易排序，减少抢跑空间。
**代价**：验证者权力大，又回到中心化问题。

## 技术难点总结

| 难点 | 解法 | 代价 |
|------|------|------|
| 共识太慢 | 少量验证者+HyperBFT | 去中心化弱 |
| 订单簿贵 | 链原生支持 | 需自建L1 |
| 清算不及时 | 清算引擎内置 | 工程复杂度极高 |
| Oracle风险 | 多源+人工兜底 | 极端情况有漏洞 |
| MEV攻击 | 验证者控制排序 | 权力集中 |

## 共识算法说明

Hyperliquid 的 HyperBFT 基于学术论文 **HotStuff**（2018年，康奈尔大学/VMware公开发表）。

Cypherium 声称Hyperliquid抄其共识算法——**不实**。两者都基于同一篇公开论文，如同两家餐厅都用公开食谱，不构成抄袭。判断这类指控：有无具体技术证据、发言方有无利益冲突、项目数据有无变化。
