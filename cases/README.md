# 案例分析

具体项目和事件的深度拆解。**方法论看不懂的地方，看案例就懂了。**

## 现有文件

| 文件 | 案例 | 提炼出的通用认知 |
|------|------|----------------|
| `01-hyperliquid.md` | Hyperliquid 全解析 | 什么样的项目才有资格自建链；Perp DEX 的技术门槛 |
| `02-ftx-exchange-tokens.md` | FTX 暴雷 + 交易所平台币 + Backpack/BP | 平台币凭什么值钱；交易所是怎么死的 |

## 和 research/ 的区别

| | `cases/` | `research/` |
|---|---------|------------|
| 时间性 | 已经定性的项目/事件，结论稳定 | 正在发生，需要持续跟踪 |
| 目的 | 从这个案例学到什么通用规律 | 这个赛道现在什么情况、下一步看什么 |
| 更新 | 基本不动 | 有新事件就更新 |
| 例子 | FTX 已经死了，结论不会变 | RGB 赛道还在跑，USDT 随时可能落地 |

调研档案里的项目**尘埃落定后**可以提炼成案例移到这里。

## 写法要求

- 案例的价值在**可迁移的规律**，每篇必须有"对 BD 的意义"或类似落点，只讲故事等于没写
- 讲失败案例要讲清**失败的机制**，不是道德评判——"挪用客户资产"是现象，"自营盘用平台币抵押借款"才是机制
- 涉及数字标注时点（市值、TVL 这类会变的东西）
